# SQL in Rust (sqlx / Diesel / SeaORM)

## Pick one and stay with it
- **sqlx** — write SQL, get compile-time verification against a real database (`query!`/`query_as!`). The right default when the team knows SQL.
- **Diesel** — a typed query DSL; the schema lives in `schema.rs`, generated by `diesel print-schema`. Compile-time safety without writing SQL, at the cost of a steeper type-error surface.
- **SeaORM** — async, entity-based, closer to a traditional ORM. Easier migration from another ORM; less control over the emitted SQL.

Two of them in one codebase means two schemas of truth. If a second one is being added, that is an ADR, not a commit.

## sqlx
- `query!` checks the SQL at **compile time** against `DATABASE_URL` or the committed `.sqlx/` cache. That cache is regenerated with `cargo sqlx prepare` and **committed**, or CI cannot build offline.
- The macro infers nullability from the schema; a `LEFT JOIN` column comes back as `Option<T>`. Overriding with `as "col!"` is telling the compiler you know better — be sure.
- The pool is cloned, not recreated: `PgPool` is already an `Arc`. Sizing it above the database's `max_connections` divided by the number of instances is how you get "too many connections" at peak.
- A transaction is a value: every query inside takes `&mut *tx`. Dropping it without `commit()` rolls back — which is the safe default, and also a silent no-op if you forgot.

## Diesel
- `schema.rs` is generated. Edit the migration, run `diesel migration run`, let it regenerate — hand-editing it makes the types lie.
- Diesel is synchronous: inside an async runtime it goes through `spawn_blocking` or `deadpool-diesel`. A blocking query on the executor thread stalls every other task.
- `.get_result()` errors with `NotFound`; `.load()` returns an empty `Vec` and no error.

## Common to all
- Migrations are files in the repository, applied in order, additive against live data. `sqlx migrate`/`diesel migration` both refuse to re-run a modified migration — editing one that has already been applied anywhere is how environments diverge.
- Tests run against the real engine in a transaction that is rolled back, or against a disposable database per run.
